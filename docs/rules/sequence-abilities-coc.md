# 序列 8～4 能力 · CoC 改编规则

整理日期：2026-10-14。序列8～4当前保留170条主动代表能力，另有110阶独立专属面板被动；主动每阶最多三条，不强制填满。技能中的灵感提升被动已移除。

## 1. 原著概念与本团规则

能力概念、所属序列与代表性表现参考下列资料。灵性消耗、距离、时长、伤害、召唤数量、控制限制和复苏代价均为本项目改编值，**不是原著数值，也不是 Chaosium 官方超凡规则**。部分能力名称是为了桌面裁定而合并或重述的标签。

本轮通过搜索索引核对资料；多数 Fandom 正文无法直接读取，不能声称逐条核对了小说全文。需要严格考据时，应进一步对照原著章节。网页各途径提供对应来源链接。

采用CoC 7e百分制属性。资源由KP手工记录，角色卡仍为只读模板。22条途径额外灵感已采用用户填表，不眠者与怪物主动技能按表修改。

## 2. 被动面板与继承

- 所有序列9不给面板加成，只配置8～4；每阶每项最多＋3。各阶专属加点分别累计，并与通用五项各＋1叠加。完整提案见[面板加成](panel-bonuses.md)。
- 旧被动的奖励骰、技能加点、再生、护甲、复苏等由新面板方案替代，不能与旧效果重复叠加。主动检定的奖励骰和惩罚骰保留。
- 灵感独立记录，22途径9～3的额外数值由用户填表决定，详见[灵感成长](spirituality.md)，不再设置灵感提升被动或旧灵性池。
- 主动能力继承低阶，标注“替代”时用新版；专属属性提升是各阶不同来源，不套用同名强化取最高值。
- 当前SAN不因POW提高而恢复。HP、伤害加值与依赖属性的技能基础重算，不重发建卡技能点，不自动恢复当前资源。
- 不眠者序列7梦魇采用用户“强制入梦”，删除序列6同名能力。按用户确认，比较施法前当前灵感：目标＜梦魇的0.5倍强制成功，目标≥1.5倍强制失败；0.5倍边界与中间区间做POW对抗。要求施术者至少4点灵感，成功／失败均支付4点，KP手工结算。

## 3. 共通施放与检定

1. 声明能力、目标与方式，满足材料、视线、已有线索或前置控制等条件。
2. 先支付卡片标注灵性，再检定；失败也消耗。规则中「另耗」是额外费用，记录/准备与释放是两个阶段，各支付该阶段费用；明确提前支付的卷轴释放不再双扣，具体卡片优先。
3. 「施法（POW）」直接以百分制 POW 为目标值；神秘学、精神分析、乔装等使用角色对应技能。不新建一个默认满值的万能技能。「按模板原检定」只做模板要求的检定，不再额外重复一次神秘学。
4. 普通成功 ≤ 目标值；困难 ≤ 向下取整的半值；极难 ≤ 向下取整的五分之一；01 大成功。目标 <50 时 96～100 大失败，目标 ≥50 时仅 100 大失败。
5. 一般属性/技能对抗比较成功等级，同等级按 CoC 一般对抗规则比较属性或技能值；仍相同则双方再掷 d100，低者胜。双方失败时能力未达成。
6. 「施法（POW）对抗闪避」是本团为有形超凡弹丸设计的攻击规则；双方至少成功才比较等级，闪避同级胜，攻击方成功而闪避失败则命中。这不改变普通枪械的 CoC 射击规则。斗殴/投掷用各自武器规则，近战反击同级攻击方胜。
7. 优势指 1 个奖励骰：共享个位，额外掷十位，选较小的**完整百分骰结果**；00 为 100。奖励与惩罚先相抵，净数量最多 2 个。骰子面板已支持这些边界和成功等级。

自动生效只免去无意义的施放检定，不免材料、距离、抗性和前提。不自动揭示全部秘密，不允许凭一句描述直接杀死半神。伤害按卡片，伤害骰不能获得奖励骰。大成功并非所有超凡能力都自动双倍伤害。

## 4. 行动、控制与复制

- 每回合按 DEX 顺序，一次主要行动；移动与武器多次攻击按 CoC / KP 场景裁定。召唤物、秘偶与施术者共享卡片规定的攻击行动，不能堆无限额外攻击。
- 反应每轮最多一次，使用后消耗施术者下次主要行动；不能再次使用反应来无限拖欠行动。提前准备的纸人等物品须实际存在。普通闪避/反击仍沿用 CoC，不因此也消耗下次行动。
- 维持能力按卡片占用行动和支付费用；未写每回合付费的只支付施放费用。范围效果逐个对抗，不能用一个成功直接控制全场。
- 对不愿者的精神控制必须对抗。持续的强制命令每回合允许目标再次 POW 对抗挣脱，受伤或明显违背生存本能时立即允许挣脱；更具体的卡片限制优先。
- 对灵体造成伤害时，普通物理护甲仅在卡片明确允许绕过时无效；灵性防护、距离、掩体与高序列抗性仍可适用。
- 记录、模仿、放牧、卷轴、藏灵等只选 KP 已定义的能力，并遵守所列序列和槽位上限。不能从模糊概述复制无限权柄。释放使用原能力的检定、目标条件与费用，再应用卡片所列削弱或额外费用。
- 高序列压制是叙事边界，由 KP 根据对手明确抗性判断；不给任何途径对低序列自动必杀，也不保证低序列控制能跨越一切位格。

## 6. 数据维护与检查

能力仍保存在 `data/pathways.js`，主动记录 `name/type/desc/cost/check/action/range/duration/rule`，被动记录 `name/type/desc/cost:0/rule`。来源放在各途径 `abilitySource`，不依赖联网即可阅读全部能力。

纯静态页面运行不需安装依赖。开发检查使用 Node 内置测试；浏览器检查另需 Playwright 与本机 Edge（可用 `LOM_BROWSER_PATH` 指定 Chromium 浏览器路径）：

```powershell
node --test tests/pathways.test.cjs tests/dice.test.cjs
# NODE_PATH 指向已安装的 Playwright 所在 node_modules 后：
node --test tests/browser.test.cjs
```

浏览器检查覆盖两个入口、四幕、68 条随机事件、封印物、全部能力卡与手机宽度布局，输出预览到 `docs/previews/`。
